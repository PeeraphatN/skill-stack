# PRD: Skill Stack MVP

สถานะ: ข้อกำหนดผลิตภัณฑ์สำหรับ MVP ยังไม่ใช่ผลยืนยันว่า installer ทำงานได้แล้ว

เอกสารนี้เป็นผลลัพธ์ของ [Issue #2: เขียน PRD](https://github.com/PeeraphatN/skill-stack/issues/2)
โดยอ้างอิง [README](../README.md) และ [Issue #1: Skill Stack MVP](https://github.com/PeeraphatN/skill-stack/issues/1)
ใช้กำหนดว่าผู้ใช้ต้องทำอะไรได้และจะตรวจรับอย่างไร ส่วนรายละเอียดทางเทคนิคเป็นงานของ SRS และ issue ถัดไป

## ปัญหา

เมื่อย้ายไปเครื่องใหม่ ผู้ใช้ต้องรวบรวมรายชื่อ skills และติดตั้งทีละรายการด้วยมือ
แต่ละแหล่งอาจใช้วิธีติดตั้งต่างกัน และตำแหน่งไฟล์หรือคำสั่งอาจต่างกันตามระบบปฏิบัติการ
เมื่อใช้ coding agents หลายตัว ผู้ใช้จึงต้องทำงานซ้ำและเสี่ยงได้ชุด skills ไม่ตรงกันระหว่าง agents หรือระหว่างเครื่อง

Skill Stack จะเก็บรายการติดตั้งไว้ในที่เดียว และเรียก installer กลางให้ติดตั้งชุดนั้นกับ agents ที่กำหนด
ผู้ใช้จึงเริ่มใช้งานเครื่องใหม่ได้โดยไม่ต้องจำคำสั่งของแต่ละแหล่ง

## ผู้ใช้และสถานการณ์หลัก

ผู้ใช้หลักคือนักพัฒนาที่ใช้ Codex, Pi หรือ Hermes และต้องการนำชุด skills ประจำไปใช้บนเครื่องใหม่
ทั้ง Linux, macOS และ Windows โดยมี Node.js, npm และสิทธิ์ติดตั้ง global skills พร้อมแล้ว
MVP รองรับการใช้หลาย agents บนเครื่องเดียว รวมถึงการติดตั้งให้ครบทั้งสามตัว

ผู้ดูแลชุด skills คือผู้ที่เพิ่มหรือปรับรายการกลางใน repository เพื่อให้การติดตั้งครั้งถัดไปใช้รายการเดียวกัน
ใน MVP ผู้ดูแลแก้ไฟล์ manifest โดยตรงได้ ยังไม่ต้องมีหน้าจอหรือคำสั่งจัดการรายการแยกต่างหาก

สถานการณ์หลักมีดังนี้:

1. ผู้ใช้เตรียมเครื่องและดาวน์โหลด repository จากนั้นเรียกคำสั่งเดียวเพื่อติดตั้งชุด skills ใน manifest
2. ผู้ใช้เปิด agents ที่กำหนดไว้ และแต่ละ agent พบ skills จากชุดติดตั้งเดียวกัน
3. ผู้ใช้เรียกติดตั้งซ้ำบนเครื่องเดิมได้ โดย skills ที่ใช้งานได้อยู่แล้วยังใช้งานต่อได้
4. หากติดตั้งไม่ครบ ผู้ใช้รู้ว่ารายการใดล้มเหลว แก้สาเหตุ และเรียกติดตั้งซ้ำได้

## เป้าหมายและผลสำเร็จ

MVP ต้องลดการติดตั้งทีละแหล่งให้เหลือคำสั่งหลัก `node install.mjs`
หลังเตรียมข้อกำหนดเบื้องต้นแล้ว ผู้ใช้ไม่ต้องเรียกคำสั่งติดตั้งแยกสำหรับแต่ละ skill หรือแต่ละ agent
คำว่า “คำสั่งเดียว” ไม่รวมการติดตั้ง Node.js, npm, coding agents หรือการดาวน์โหลด repository

ชุด skills ต้องมาจาก `manifest.json` เพียงแห่งเดียว และติดตั้งผ่าน `npx skills`
โดยให้ skills CLI ดูแล global source ผ่าน `~/.agents/skills` และ symlink ไปยัง agents
Skill Stack ไม่สร้างระบบจัดการ symlink ของตัวเอง

ถือว่า MVP สำเร็จเมื่อผ่าน acceptance criteria ด้านล่างบนทั้งสามระบบปฏิบัติการ
รวมถึงการติดตั้งครั้งแรก การติดตั้งซ้ำ และการรายงานเมื่อมีรายการติดตั้งไม่สำเร็จ
ยังไม่ตั้งเป้าเวลาติดตั้งเป็นวินาที เพราะขึ้นกับเครือข่ายและแหล่ง skills ภายนอก

## ขอบเขต MVP

### รายการ skills

รองรับแหล่งต่อไปนี้ซึ่ง README และ Issue #1 เลือกไว้สำหรับการติดตั้งผ่าน `npx skills add`:

- `DietrichGebert/ponytail`
- `petergyang/no-ai-slop`
- `mattpocock/skills`
- `thananon/9arm-skills`

รายการนี้ระบุแหล่งต้นทาง ยังไม่ยืนยันว่าทุก repository มี skill เดียวหรือต้องติดตั้งทุก skill ภายในนั้น
ชื่อ skills ที่ติดตั้งจริง วิธีเลือกจาก repository และชื่อ agent ที่ CLI ยอมรับต้องสรุปใน Issue #4
ก่อนนำไปออกแบบ manifest และ installer โดยต้องยังครอบคลุมแหล่ง MVP ทั้งสี่แห่ง

### ความสามารถที่ต้องมี

- ใช้ `manifest.json` ระบุแหล่ง skills และ agents เป้าหมาย โดยไม่ต้องแก้รายการซ้ำใน installer หรือ wrapper
- มี `install.mjs` เป็นทางเข้าหลักข้ามแพลตฟอร์ม และ `install.sh` กับ `install.ps1` เป็น wrapper สำหรับ shell และ PowerShell
- ติดตั้งแบบ global ผ่าน `npx skills add` ให้ Codex, Pi และ Hermes ใช้ชุด skills เดียวกัน โดย skills CLI จัดการ source และ symlink
- ติดตั้งซ้ำได้โดยไม่ทำให้ skills เดิมเสีย ไม่สร้างรายการซ้ำ และไม่ลบ skills ที่อยู่นอกรายการของ Skill Stack
- แสดงผลว่าติดตั้งสำเร็จครบหรือไม่ พร้อมรายการที่ล้มเหลวและแนวทางแก้เบื้องต้นใน README

การรันซ้ำหมายถึงติดตั้งรายการเดิมได้อย่างปลอดภัย ไม่ได้ให้สัญญาว่าจะตรึงเนื้อหา skills ให้เหมือนเดิมทุกครั้ง
นโยบายเวอร์ชันและการอัปเดตต้องระบุในงานออกแบบถัดไป ห้ามถือว่าการรันซ้ำคือคำสั่ง update โดยอัตโนมัติ

### สิ่งที่ผู้ใช้ต้องเตรียม

ผู้ใช้ต้องมี Node.js และ npm ที่เรียกใช้ได้ มีเครือข่ายเข้าถึงแหล่งติดตั้ง
มีสิทธิ์เขียนตำแหน่ง global skills และสร้าง symlink ตามที่ skills CLI ต้องการ
รวมถึงติดตั้ง agents ที่จะใช้ตรวจรับไว้แล้ว README ต้องบอกเวอร์ชันและเงื่อนไขที่ผ่านการทดสอบจริง
เมื่อเงื่อนไขไม่พร้อม ระบบต้องแจ้งสาเหตุที่ผู้ใช้แก้ต่อได้ โดยไม่รายงานว่าติดตั้งครบ

## นอกขอบเขต MVP

- แหล่งที่ใช้วิธีติดตั้งเฉพาะ ได้แก่ `trailhq/Trail-Code`, `ayghri/i-have-adhd`, `Ar9av/obsidian-wiki` และ `multica-ai/andrej-karpathy-skills`
- คำสั่งตรวจสอบสถานะและ update แบบเฉพาะ เป็นงาน Issue #10; MVP มีผลสรุปจากการติดตั้งและวิธีตรวจสอบด้วยตนเองใน README
- การเขียน ติดตั้ง หรือ publish custom skills รวมถึง private skills และการจัดการ credentials; MVP เตรียมให้เพิ่มรายการใน manifest ได้เท่านั้น
- การติดตั้งผ่าน `npx github:<owner>/skill-stack`, หน้าจอจัดการ และระบบจัดการ symlink ของ Skill Stack เอง
- การติดตั้ง Node.js, npm หรือ coding agents ให้ผู้ใช้ รวมถึงการรับรอง agents อื่นนอก Codex, Pi และ Hermes

## Acceptance criteria

เกณฑ์เหล่านี้ใช้ตรวจรับผลิตภัณฑ์เมื่อพัฒนา MVP เสร็จ การมี PRD ฉบับนี้ไม่ได้หมายความว่าผ่านการทดสอบแล้ว

### AC-01: ติดตั้งครั้งแรกด้วยคำสั่งเดียว

บนเครื่องหรือสภาพแวดล้อมทดสอบที่ยังไม่มี skills ชุด MVP และเตรียมข้อกำหนดเบื้องต้นครบแล้ว
เมื่อเรียก `node install.mjs` จาก repository ระบบต้องติดตั้งรายการที่กำหนดใน manifest ได้ครบจากทั้งสี่แหล่ง
โดยผู้ใช้ไม่ต้องเรียกคำสั่งติดตั้งแยกต่อ skill หรือ agent และต้องแสดงผลสำเร็จครบอย่างชัดเจน

### AC-02: ใช้ manifest เป็นรายการกลาง

เมื่อผู้ดูแลเพิ่มหรือเอารายการ skill ออกจาก manifest การติดตั้งครั้งถัดไปต้องใช้รายการที่แก้แล้ว
โดยไม่ต้องแก้ `install.mjs` หรือ wrappers การเอารายการออกหมายถึงไม่ติดตั้งรายการนั้นในครั้งถัดไป
ไม่ใช่คำสั่งลบ skill ที่เคยติดตั้งไปแล้ว

### AC-03: Agents พบ skills จาก global source

หลังติดตั้งสำเร็จ ต้องตรวจพบ global source ตามโครงสร้าง `~/.agents/skills` ของ skills CLI
และ symlink ที่ CLI จัดการให้ agents เป้าหมาย โดย Codex, Pi และ Hermes ต้องค้นพบ skills ตาม manifest ได้จริง
บน Windows ให้ตรวจตำแหน่งเทียบเท่าภายใต้ home ของผู้ใช้ตามที่ CLI ใช้ ไม่อาศัยเพียงข้อความว่าสร้าง symlink สำเร็จ

### AC-04: ติดตั้งซ้ำไม่ทำให้ของเดิมเสีย

หลังผ่าน AC-01 ให้ติดตั้ง skill อื่นที่ไม่อยู่ใน manifest ไว้ด้วย แล้วเรียกคำสั่งเดิมซ้ำ
skills ชุด MVP ต้องยังถูก agents พบได้ ไม่มีสำเนาติดตั้งซ้ำจากการรันครั้งที่สอง
และ skill ที่อยู่นอก manifest ต้องยังอยู่และใช้งานได้ หากพบข้อมูลเดิมที่ขัดแย้งจนติดตั้งต่ออย่างปลอดภัยไม่ได้
ต้องแจ้งปัญหาแทนการลบหรือแทนที่ข้อมูลนั้นโดยเงียบ

### AC-05: ใช้ได้บนสามระบบปฏิบัติการ

ต้องมีหลักฐานการทดสอบ AC-01, AC-03 และ AC-04 บน Linux, macOS และ Windows
โดยระบุรุ่น OS, Node.js, skills CLI และ agents ที่ใช้ทดสอบ
`install.sh` บน Linux/macOS และ `install.ps1` บน Windows ต้องเรียกการติดตั้งชุดเดียวกับ `node install.mjs`
ได้สำเร็จตามเงื่อนไขที่ README ระบุ

### AC-06: แจ้งความล้มเหลวและลองใหม่ได้

เมื่อ Node.js/npm ไม่พร้อม สิทธิ์ไม่พอ หรือดึงแหล่ง skill ไม่สำเร็จ
ทางเข้าที่ผู้ใช้เรียกต้องแจ้งสาเหตุที่ตรวจพบและจบด้วยสถานะไม่สำเร็จ โดยไม่สรุปว่าติดตั้งครบ
กรณีติดตั้งบางรายการสำเร็จแล้วต้องแยกผลสำเร็จและล้มเหลวให้เห็น
เมื่อแก้สาเหตุและเรียกใหม่ ต้องติดตั้งให้ครบได้โดยไม่ต้องล้างชุดที่สำเร็จไปแล้วด้วยมือ

### AC-07: เอกสารพาผู้ใช้ติดตั้งและตรวจผลได้

ผู้ทดสอบต้องทำตาม README ตั้งแต่เตรียมเครื่อง เรียกคำสั่งติดตั้ง และตรวจว่า agents พบ skills ได้
โดยไม่ต้องอ่าน source code เมื่อพบความล้มเหลวใน AC-06 README ต้องมีแนวทางแก้เบื้องต้นและวิธีเรียกซ้ำ
การตรวจผลในเกณฑ์นี้ใช้คำแนะนำตรวจด้วยตนเองได้ ไม่ต้องรอคำสั่ง status จาก Issue #10

## งานที่ต้องยืนยันก่อนพัฒนา

PRD นี้กำหนดผลลัพธ์ที่ต้องการ ไม่ยืนยันความสามารถปัจจุบันของ `npx skills` หรือ repositories ภายนอก
Issue #4 ต้องตรวจชื่อ agents ที่รองรับจริง วิธีติดตั้งแต่ละแหล่ง พฤติกรรม global source/symlink
รวมถึงข้อจำกัดบน Windows และสิทธิ์ที่ต้องใช้ หากข้อเท็จจริงทำให้ทำตาม PRD ไม่ได้
ต้องบันทึกข้อจำกัดและปรับขอบเขตอย่างชัดเจนก่อนพัฒนา ไม่ตัดการรองรับ OS หรือ agent ออกโดยเงียบ

SRS ใน Issue #3 และงาน manifest ใน Issue #5 ต้องกำหนดรูปแบบข้อมูล การเลือก skills จากแต่ละแหล่ง
นโยบายเวอร์ชัน พฤติกรรมเมื่อพบข้อมูลเดิม และรายละเอียดการรายงานข้อผิดพลาดให้ทดสอบตามเกณฑ์ข้างต้นได้
ส่วนการเขียน installer, wrappers และการทดสอบข้าม OS อยู่ใน Issue #6–#9
การส่งมอบ Issue #2 จึงจำกัดอยู่ที่เอกสารข้อกำหนดและลิงก์ให้ค้นพบเอกสารนี้ได้
